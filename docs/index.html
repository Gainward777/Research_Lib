Руководство по использованию

Research Library

Бот-библиотекарь принимает на русском языке вопросы, отчёты, фотографии и документы, сохраняет материалы через GBrain и отвечает на основе содержимого библиотеки.

LLM-роутер получает текст, вложения, Telegram-метаданные и контекст диалога. Он выбирает зарегистрированный скилл, но сам не отвечает пользователю и не сохраняет данные. Неоднозначный запрос возвращается пользователю как уточняющий вопрос.

Важно. Ответ на вопрос формирует GBrain. Бот передаёт текст ответа без перефразирования и собственных дополнений; допускается только техническое разбиение длинного текста на сообщения Telegram.

Что можно сохранить

Произвольный текст, пересланные сообщения, отчёты, отдельные фотографии, альбомы и документы. Несколько сообщений можно собрать в один материал.

Как задавать вопросы

Обычной русской фразой или через /ask. Для выдачи совпадений без синтеза ответа используйте естественную просьбу найти материалы или /search.

Развёртывание на Railway

  1. Создайте сервис из GitHub-репозитория. Railway соберёт корневой Dockerfile; отдельная установка GBrain не нужна — он фиксированной версии собирается внутри образа.
  2. Подключите постоянный том. Смонтируйте Railway Volume в /data/library. Без него материалы и индексы будут потеряны при пересоздании контейнера.
  3. Добавьте переменные. Минимальный набор приведён ниже. Railway сам задаёт PORT, вручную добавлять его не требуется.
  4. Настройте healthcheck. Укажите путь /healthz. Для проверки готовности хранилища и GBrain используйте /readyz.
  5. Запустите deploy. Приложение поднимет REST/MCP сервер, миграции SQLite и Telegram polling, если задан TELEGRAM_BOT_TOKEN.
  6. Проверьте результат. Откройте https://ВАШ-ДОМЕН/healthz, затем /readyz, отправьте боту вопрос и тестовый материал.

Разделы и индивидуальные токены

Каждый материал относится к одному разделу: memento/<project> или research/<workspace>. Токен разработчика, агента, CI или сервиса получает read, publish либо admin только для нужных разделов.

Первый администратор

uv run library-admin tokens bootstrap --name platform-admin

Сохраните поле token в password manager: повторно оно не отображается.

Токен агента

uv run library-admin --token "$ADMIN_TOKEN" tokens create \\
  --name backend-agent --subject-type agent \\
  --grant memento/backend:read,publish

REST и MCP принимают один формат: Authorization: Bearer rl_<prefix>_<secret>. Недоступный item возвращается как 404. Search обращается только к разрешённым non-federated GBrain sources.

Модель доступа и ротация: docs/access-control.md. Пошаговый production rollout Telegram, backup и backfill: docs/access-rollout-runbook.md.

Использование Telegram-бота

Основной интерфейс — естественный русский язык. Slash-команды являются необязательными алиасами тех же прикладных скиллов.

Задать вопрос

«Какие ограничения были у эксперимента с RAG?»

Вызывается ask_library, исходный вопрос передаётся в GBrain.

Найти материалы

«Найди отчёты про векторный поиск»

Вызывается search_library; возвращаются совпадения без синтеза ответа.

Сохранить отчёт

Отправьте или перешлите текст, фотографию, альбом либо документ и напишите: «Сохрани это как отчёт».

Собрать несколько сообщений

Напишите «Начни сбор материала», пришлите части и вложения, затем «Закончи и сохрани».

Сценарий составного материала

  1. Отправьте /collect или естественную фразу «Начни собирать один материал».
  2. Присылайте текст, пересланные сообщения, фото, альбомы и документы. Они добавляются через append_collection.
  3. Отправьте /save или «Закончи сбор и сохрани». Скилл finish_collection передаст всё в GBrain единым материалом.
  4. Для отмены используйте /cancel или «Отмени сбор».

Поиск

curl -X POST "https://ВАШ-ДОМЕН/v1/search" \
  -H "Authorization: Bearer $LIBRARY_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"query":"векторный поиск","limit":10}'

Создание заметки

curl -X POST "https://ВАШ-ДОМЕН/v1/items" \
  -H "Authorization: Bearer $LIBRARY_ACCESS_TOKEN" \
  -H "Idempotency-Key: note-2026-08-18-001" \
  -H "Content-Type: application/json" \
  -d '{
    "section":{"domain":"research","key":"main"},
    "type":"note",
    "title":"Наблюдение по эксперименту",
    "content":"Полный текст материала",
    "tags":["rag","experiment"]
  }'

Допустимые типы: experiment, experiment-report, idea, publication, method, concept, model, dataset, source, note.

Подключение внешнего MCP-клиента

Сервис публикует Streamable HTTP endpoint POST /mcp. К нему подключается другой сервис или агент по HTTPS и передаёт выданный ему project-scoped Bearer-токен.

URL: https://ВАШ-ДОМЕН/mcp
Authorization: Bearer rl_<prefix>_<secret>
Transport: Streamable HTTP
В репозитории и Railway-контейнере не устанавливается Codex и не запускается MCP-клиент. Здесь работает только MCP-сервер библиотеки. Внешний клиент настраивается в собственном репозитории или окружении.

Memento: общая память агентов

Linear остаётся источником задач, Git — источником кода, а Библиотека хранит причины решений, подтверждённые результаты и состояние реализации. Codex, Cursor и Claude Code подключаются к /mcp как внешние клиенты.

Найти контекст

{
  "query": "Пользователя периодически выбрасывает из системы",
  "project": "platform",
  "repository": "backend-api",
  "work_item": "BUG-731",
  "limit": 20
}

Старая задача, файл и commit не обязательны: GBrain ищет по всей сохранённой истории и возвращает фиксированные блоки реализаций, решений, проблем, тестов и checkpoints.

Опубликовать контекст

{
  "payload": {
    "context_kind": "decision",
    "project": "platform",
    "repository": "backend-api",
    "work_item": "AUTH-142",
    "title": "Шифрование refresh token",
    "content": "Refresh token шифруется перед сохранением.",
    "created_by": "agent",
    "verification": "unverified",
    "consulted_context_item_ids": ["lib_использованный_источник"]
  },
  "idempotency_key": "memento:AUTH-142:decision:1"
}
Записи неизменяемы. Исправление публикуется новой записью с supersedes_item_id. Фактически использованный контекст перечисляется в consulted_context_item_ids и сохраняется отношениями has-source.

Канонические сценарии находятся в agent-skills/: поиск контекста, запись знания, checkpoint перед переключением и возобновление работы.

Наблюдаемость

Research Library отправляет агрегированные метрики в Grafana Cloud по OTLP/HTTPS, а структурированные JSON-логи пишет в Railway stdout. Grafana не запускается внутри контейнера библиотеки.

METRICS_ENABLED=true
OTEL_METRICS_EXPORTER=otlp
OTEL_EXPORTER_OTLP_ENDPOINT=https://<grafana-cloud-otlp-endpoint>
OTEL_EXPORTER_OTLP_HEADERS=Authorization=Basic <secret>
METRICS_ALLOWED_PROJECTS=platform,research

Опциональный /metrics предназначен для локального/self-hosted Prometheus и всегда защищён отдельным токеном:

METRICS_ENDPOINT_ENABLED=true
METRICS_AUTH_TOKEN=<отдельный-секрет>

curl -H "Authorization: Bearer $METRICS_AUTH_TOKEN" \
  https://ВАШ-ДОМЕН/metrics
  • Каждый HTTP/MCP запрос получает request_id; он возвращается в X-Request-ID и связывает метрики с Railway logs.
  • Query, content, MCP payload, токены и document IDs не становятся metric labels.
  • Неизвестный project нормализуется в _unknown.
  • Недоступность OTLP backend не ломает REST, MCP, Telegram и retry worker.

Готовый dashboard и alert rules находятся в deploy/grafana/. Полная инструкция — в docs/observability.md.

Данные и резервное копирование

/data/library/
├── brain/                  # Markdown-страницы GBrain
│   └── attachments/        # изображения и документы
├── gbrain/                 # PGLite и внутренние данные GBrain
└── library.sqlite3         # задания, метаданные, идемпотентность

Резервируйте весь /data/library. Минимально необходимы brain/, brain/attachments/ и library.sqlite3; копия каталога gbrain/ ускоряет восстановление индекса.

Используйте одну реплику Railway: локальные SQLite/PGLite и последовательные операции GBrain не рассчитаны на одновременную запись из нескольких контейнеров в один том.

Проверка и диагностика

Признаки корректного запуска

  • /healthz отвечает HTTP 200 и {"status":"ok"}.
  • /readyz отвечает HTTP 200; проверки хранилища, SQLite и GBrain имеют значение true.
  • В Railway logs нет бесконечного restart loop и ошибок инициализации GBrain.
  • Бот отвечает на русском, сохраняет тестовый материал, а последующий вопрос находит его содержание.
  • После redeploy сохранённый материал остаётся доступен — это подтверждает работу Volume.

Локальный запуск

Docker

docker build -t research-library .
docker run --rm -p 8000:8000 \
  --env-file .env \
  -v research-library-data:/data/library \
  research-library

Разработка без Docker

cp .env.example .env
uv sync
uv run uvicorn controllers.api.app:app --app-dir src --host 0.0.0.0 --port 8000

При запуске без Docker команда gbrain должна быть доступна локально. Подробности разработки находятся в DEVELOPMENT.md, архитектурные ограничения — в arch.md.

Проверочный список безопасности

  • Задайте ALLOWED_TELEGRAM_USER_IDS или ALLOWED_TELEGRAM_CHAT_IDS.
  • Включите LIBRARY_AUTH_ENABLED=true, сохраните LIBRARY_TOKEN_PEPPER в Railway Variables и выдавайте отдельный токен каждому субъекту.
  • Для /metrics используйте третий отдельный METRICS_AUTH_TOKEN.
  • Не добавляйте токены в Git; храните их только в Railway Variables или локальном .env.
  • Не публикуйте содержимое Railway logs, если в них могут быть пользовательские материалы.
  • Регулярно создавайте резервную копию Volume и проверяйте восстановление.
  • Не включайте несколько реплик сервиса для одного тома.
